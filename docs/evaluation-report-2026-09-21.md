## 1. 指标定义与计算公式

### 1.1 检索指标

设某题检索返回按排名排列的片段 $R_1, R_2, \dots, R_K$，$rel(i) \in \{0,1\}$ 表示第 $i$ 条是否命中标注，$|G|$ 为该题标注的正确片段总数。

**命中判定**（`is_relevant`）：忽略空格和换行后，检索片段与某条标注**互为子串**，或两者的 **3-gram Jaccard 相似度 ≥ 0.6**。

#### Recall@k（召回率）

```
Recall@k = min( 1,  Σ(i=1..k) rel(i)  ÷  |G| )
```

前 k 条结果中命中的正确片段数 ÷ 该题标注的正确片段总数。

> 取 min 截断的原因：当前实现按检索结果**逐条**判定命中，未与标注做一一匹配，多个检索片段可能对应同一条标注，命中数可能超过 |G|。

#### Precision@k（精确率）

```
Precision@k = Σ(i=1..k) rel(i) ÷ k
```

前 k 条结果中正确片段数 ÷ k。分母是实际返回条数（返回值不足 k 时按实际数量算）。

#### Hit@k（命中率）

```
Hit@k = 1  若 Σ(i=1..k) rel(i) ≥ 1
      = 0  否则
```

再对全部题目取平均。回答"有多少比例的题目至少找到了一条相关内容"。

#### MRR（平均倒数排名）

```
MRR = (1/N) · Σ(q=1..N) 1 / r_q
```

$r_q$ 为该题第一条正确片段所在的排名，没找到记 0。满分 1.0 表示每题第一名就是正确片段。

#### nDCG@k（归一化折损累计增益）

```
DCG@k  = Σ(i=1..k) rel(i) / log₂(i+1)
IDCG@k = Σ(i=1..min(|G|,k)) 1 / log₂(i+1)
nDCG@k = min(1, DCG@k / IDCG@k)
```

带排序位置权重的命中指标——排得越靠前权重越高。比 Recall/Hit 更严格，能区分"正确片段排第 1 还是排第 10"。

> 实现细节：源码写的是 `sum(r / math.log2(i + 2) for i, r in enumerate(topk))`。`enumerate` 从 0 开始，故第 1 条权重为 $1/\log_2 2 = 1$，与上面 1-based 公式等价。

### 1.2 生成指标（RAGAS 0.4.3）

以下公式与 `ragas 0.4.3` 的实现逐条核对过。

#### Faithfulness（忠实度）

```
Faithfulness = 答案中能被检索上下文支持的陈述数 ÷ 答案拆分出的陈述总数
```

两阶段：

1. **拆分**：LLM 把答案拆成一个或多个"完全可独立理解、不含代词"的陈述（`StatementGeneratorPrompt`）。
2. **判定**：把**全部检索上下文拼接成一个字符串**（源码：`contexts_str = "\n".join(retrieved_contexts)`），与所有陈述一起交给 LLM 逐条做 NLI 判定（`NLIStatementPrompt`）。

拆分不出任何陈述时记 NaN。

#### Answer Relevancy（答案相关性）

```
AR = (1/N) · Σ(i=1..N) cos( E(q_原), E(q_i) )  ×  [ not all_noncommittal ]
```

1. LLM 依据**答案本身**反向生成 N 个可能对应的问题（N = `strictness`，默认 **3**），同时判断该答案是否属于**回避性回答**（noncommittal，如"我不知道"）。
2. 嵌入模型分别编码生成的问题与原始问题，算**余弦相似度**并取平均。

```
cos(a, b) = (a · b) / (‖a‖ · ‖b‖)
```

若 N 个生成问题**全部**被判为回避性，整体乘 0（这就是拒答题得 0 分的原因）。

> **本项目的关键适配**：RAGAS 通过一次 `n=3` 的多候选请求实现 N=3，但 DeepSeek 只支持 `n=1`（直接返回 400 `Invalid n value`）。因此启用 `LangchainLLMWrapper(..., bypass_n=True)`，改为发 3 次独立的单条请求，指标语义不变。

#### Context Precision（上下文精确率）

```
CP = Σ(k=1..K) ( Precision@k × v_k )  ÷  Σ(k=1..K) v_k

其中  Precision@k = ( Σ(i=1..k) v_i ) ÷ k
     v_k ∈ {0,1} = 第 k 个上下文与参考答案的相关性判定
```

即**平均精度（Average Precision）**：对每个检索到的上下文，让 LLM 判断"这段内容对得出参考答案是否有用"（`ContextPrecisionPrompt`，输入含问题、上下文、参考答案），再按排名位置加权平均。

> **注意它依赖参考答案**：判定的是"这段上下文能不能支撑参考答案"，不是"和问题相关吗"、也不是"用上了吗"。这解释了 table 类为什么偏低——它要求上下文足以支撑参考答案里的**全部要点**。

#### Context Recall（上下文召回率）

```
CR = 参考答案中能归因到检索上下文的陈述数 ÷ 参考答案拆分出的陈述总数
```

把**参考答案**拆成陈述，逐条判断能否从拼接后的检索上下文里得到（`attributed ∈ {0,1}`），取平均。

### 1.3 辅助校验：确定性数字校验

RAGAS 的指标都依赖 LLM 判分，存在主观性。为交叉验证，另做一套**不依赖模型**的确定性校验：

```
数字有据率 = 答案中能在检索上下文中逐字找到的「数字+单位」token 数
           ÷ 答案中抽取到的「数字+单位」token 总数
```

- **抽取规则**：正则匹配 `数字 + 单位`，单位为 `万亿|亿|万|千瓦时|千瓦|兆瓦|个|家|台|座|吨|米|%|倍|年|月|日|小时` 等。
- **匹配方式**：两边都去掉空格换行后做**子串匹配**。
- **已知盲区**：文档用中文数字（"一九八九年"）而答案用阿拉伯数字（"1989年"）时会被误判为无据；"占比约23%"与文档"23.7%"这类四舍五入也判为不匹配。因此该指标给出的是**下界**，人工复核时需剔除这些情况。

### 2.1 总体

113 题参与（8 道 negative 题无 `relevant_chunks` 标注，跳过）。

### 2.3 判分口径的一个已知缺陷

8 道"零命中"题，我把它们的标注文本逐条拿去 `data/chunks.pkl`（1625 个片段）里查过：**全部都能在库里找到**（≥30 字连续命中）。零命中的原因是**标注与入库片段的边界不一致**——比如库里是"这是一张柱状图…"，标注写的是"这张图片是一张柱状图…"，双向子串都不成立，短标注的 3-gram Jaccard 又掉到 0.6 阈值以下。

因此上面所有 Recall 数值都是**下界**。极端假设这 8 题全为真命中时的上界：

| 配置 | Recall@5（报告值） | Recall@5（上界） |
|---|---|---|
| hybrid_only | 0.8525 | 0.9764 |
| hybrid_rerank | 0.9145 | 0.9853 |

全部 113 题里，只有 1 条标注（生物柴油图）在库中确实找不到，可能是人工改写过度。

## 5. 真实短板与错误样本

### 5.1 两个短板题型

**table（Context Precision 0.7064，全场最低）**

根因已定位到抽取层：PDF 表格被拍平为文本时**列粘连**。原文实例（特高压题检索到的上下文）：

```
…±800千伏特高压直流输电工程2025年5月8002哈密—重庆±800千伏特高压直流输电工程2025年6月8003宁夏—湖南…
```

"额定容量"列的 `800` 与下一行序号 `2` 粘成了 `8002`，**容量列实际丢失**。该题答案"800万千瓦"是对的（与参考答案一致），但上下文里查不到——属于"对的答案、无据的证据"。

**figure（Faithfulness 0.7278，全场最低）**

图内数据依赖 VLM 生成的文字描述入库，图上的数据点很多没有被写进描述。同时 15 道图题中有 5 道的标注与入库片段对不上（其他题型 0~1 条），**这部分分数偏低是标注问题而非检索问题**。

### 5.2 值得进 case 库的真实错误

1. **无据硬答**（最该修的行为）：电力现货市场时间要求题检索零命中，模型用参数记忆作答，答"2025年底前基本实现全覆盖"，正确是"2027年前基本实现正式运行"。**没有依据时应当拒答。**

2. **表格串数**：绿证消费主体题，正确答案 5.9万个 / 企业 5.54万家，答成 7.34万个 / 6.32万家，还把"个人买家3955**名**"答成"3955**万名**"。这是本语料最危险的错误类型。

3. **幻觉式的"无数据"声明**：生物柴油题，图中数据未入库，模型给出"占比约23%"并声称"文档中未提供其他国家的产量和占比数据"——而文档里就有 23.7% / 21.5% / 19.4%。

4. **指标串位**：非化石能源发电量占比题，把"新能源装机占比 50%"串成"新能源发电量占比 50%"，正确是 30%。

## 6. 已知的度量口径问题

以下问题会让报告数字失真，引用前请注意。

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | negative 题混入四个 RAGAS 均值 | Answer Relevancy 被压低约 0.05，Context Precision 约 0.06 | 单独统计拒答率 |
| 2 | Faithfulness 约一半低分是误报 | 绝对值偏低且区分度低 | 用确定性数字校验交叉验证 |
| 3 | `is_relevant` 判分口径与切分边界不一致 | 8/113 题被误判为完全未命中，Recall 数值是下界 | 标注改用 `chunk_id`，或先做标注→片段的最近邻对齐 |
| 4 | 重排后只返回 5 条 | `hybrid_rerank` 行的 @10 恒等于 @5 | 不要与 `hybrid_only` 的 @10 并列 |
| 5 | figure 题标注与库中片段不一致 | 5/15 图题分数偏低是标注问题 | 先修标注一致性再优化检索 |
| 6 | 数字校验有盲区 | 中文数字、四舍五入被误判为无据 | 人工复核时剔除 |

## 7. 结论与建议

### 结论

1. **生成质量真实水平好于报告数字**：真实幻觉率约 3%，主要被指标误报和 negative 题双重低估。
2. **检索短板比报告数字更集中**：table / figure 两类是全链路瓶颈，且 table 的问题根源在 PDF 抽取层而非检索算法。
3. **重排收益可信**：MRR +0.089、Recall@1 +0.12，这是可对外沟通的一组数字。
4. **判分模型换成外部 API 后指标可用性提升明显**，但 faithfulness 的可靠性问题不是换模型能解决的——它是这个指标在中文长答案语料上的固有局限。

### 建议（按性价比排序）

1. **negative 题单列指标**（拒答率 / 误答率），不混入均值 —— 零成本，立刻让报告数字变准。
2. **把确定性数字校验加进评测脚本**，作为 faithfulness 的常驻交叉验证指标 —— 成本几乎为零，且能抓到 faithfulness 漏掉的真错误。
3. 修 `is_relevant` 判分口径（标注改 `chunk_id` 或做最近邻对齐）—— 让 Recall 数值从下界变成真值。
4. 表格抽取列粘连是下一个投入点 —— 按列坐标切分，或对表格区域走结构化抽取。
5. figure 题先对齐标注，再谈检索优化。
