# 代码规范

项目使用 Ruff 统一格式和基础静态检查，配置集中在 pyproject.toml。
格式目标为每行 100 个字符，采用四空格缩进、标准导入顺序和一致的多行调用格式。
变量、类、函数及第三方 API 标识保持英文，解释性注释和文档字符串使用中文。

## 函数说明

每个具名函数在函数体开头使用中文文档字符串，包含构造方法、私有方法、
接口声明、测试函数和嵌套辅助函数。简短函数用一句话说明作用和结果：

    def file_hash(path: str | Path) -> str:
        """按固定大小分块计算 SHA-256，避免把整份 PDF 一次性读入内存。"""

对构建索引、配置读取、召回降级等较复杂的函数，补充关键输入含义、
返回结果、异常条件或副作用。不机械重复函数名，也不要求简单函数重复列出所有参数。
不确定第三方对象具体类型时保留其灵活性，不添加不准确的类型声明。

注释用具体、容易理解的话说明“接收什么、做什么、返回什么”。例如：

- “生成配置快照”改为“读取 config.toml 并返回 Settings 配置对象”。
- “发布片段缓存与清单”改为“把片段和文件哈希清单保存到磁盘”。
- “注入加载工厂”改为“允许传入自定义模型加载函数”。

可以保留 Milvus、BM25 等实际使用的名称，但不堆砌抽象术语，也不逐行解释普通语句。

关键注释说明容易误解的规则，例如参数之间的关系、处理顺序、失败后的行为和实现范围。
说明必须与代码一致：文件存在检查不能写成“保证模型完整”，字符重合率不能写成
“验证答案事实正确”。已有说明清楚时不重复添加，每个关键逻辑段通常一两句即可。

## 实现习惯

- 公共数据入口和返回结构优先增加类型标注，帮助调用者理解约定。
- 变量名说明业务含义，例如 target_paths、failed_sources、merged_chunks。
- 复杂判断优先使用命名条件或显式分支，减少嵌套三元表达式。
- 按职责提取辅助函数，例如切分器创建、参数校验、批量解析、单文档评分。
- 返回字段较多的数据结构时使用关键字参数，避免依赖位置记忆。
- 注释解释顺序、约束和原因，例如为何先解析再删旧数据、为何 RRF 要分支内去重。
- 可直接从代码读出的普通赋值和简单循环不逐行添加重复注释。
- 工具指令如覆盖率排除或静态检查忽略标记须保留合法语法，中文说明另行书写。

## 长表达式排版

每行 100 字符是格式目标，不是必须写满的长度。优先让每一行只表达一个清晰步骤：

- 多参数调用按参数分行，最后一个参数保留尾逗号，让 Ruff 保持展开布局。
- 条件选择后还要调用方法时，优先展开为 if/else，最后统一处理结果。
- 嵌套推导式改成普通循环；简单、短小的单层推导式可以保留。
- 单层推导式优先通过换行区分结果表达式与遍历语句，不因属性访问较长就改成普通循环。
- 存在多个处理步骤或复杂分支时，再使用普通循环。
- 为保留明确选定的多行布局，可在该语句末尾使用 fmt: skip；其余代码继续由 Ruff 格式化。
- 分数数量检查、数值有效性检查等独立校验分开书写；排序和截取结果也分成两步。
- 连续调用、解码后取值和复杂公式可拆成有含义的中间变量，保持原计算顺序。
- 不依赖手动换行维持复杂三元表达式的外观，因为格式器可能将其重新合并。

例如，兼容消息对象和字符串时写成：

```python
if hasattr(result, "content"):
    answer = result.content
else:
    answer = str(result)
return answer.strip()
```

模型加载参数按行排列：

```python
self._model = factory(
    model_name=str(self.settings.path),
    model_kwargs={"device": self.settings.device},
    encode_kwargs={"normalize_embeddings": True},
)
```

## 本地检查

安装开发依赖后执行：

    python -m pip install ".[dev]"
    ruff check main.py src scripts tests
    ruff format --check main.py src scripts tests
    python -m scripts.check_docstrings
    python -m pytest -q

需要统一格式时执行：

    ruff format main.py src scripts tests

中文说明检查使用 AST 读取文档字符串，不导入项目模块或加载模型。
上述检查可以发现缺失说明及常见代码问题，但注释是否准确仍需结合实现审查。
格式和回归测试通过，不等于真实 OCR、Milvus、GPU 和 RAGAS 链路已验证。
