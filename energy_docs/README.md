# 中文能源电力公开文档采集器

采集各级政府与行业机构**公开发布**的能源电力政策、法规、通知、公告，
输出可直接用于语言模型训练或领域研究的中文文本。

---

## 一、先读这段：能拿到多少

**这一节的数字是实测的，不是估算。**

### 单篇体量

| 类型 | 篇幅 | 例 |
|---|---|---|
| 法律法规 | 5,000 ~ 20,000 字 | 《中华人民共和国能源法》9,233 字 |
| 政策通知 | 500 ~ 4,000 字 | 《关于加快推动新能源场站配建储能高质量发展的通知》3,729 字 |
| 公告公示 | 150 ~ 800 字 | 许可证变更公告 |

### 到 1GB 需要多少篇

按平均 1,500 字（约 4.5 KB）算：

**1GB ≈ 22 万篇。**

而现实是：全国约 30 个省级能源主管机构加国家能源局，**每个栏目页首屏约 15~45 条**。
即使把所有机构的栏目都加上，首屏可得的量级在**几千到几万篇**，折合 **几十到几百 MB**。

### 结论

**这条路走不到 GB。** 差一个数量级。

原因不是工具不行，是中文能源领域的公开文档**总量就这么大**——
政策文件不像专利或论文那样有海量存量。如果你需要 GB 量级，
要么回到专利渠道（需要数据库账号），要么接受一个更小的目标。

工具每次运行都会报告实际体量和「按当前体量到 1GB 还需多少篇」，你可以随时校准。

## 二、合规边界

- ✅ 只采集**公开发布**的政府/行业文档页面
- ✅ 默认请求间隔 2 秒，单线程，可断点续传
- ✅ 被拦截或站点维护时立即停止
- ❌ 不绕过任何访问控制（不破验证码、不伪造会话）
- ❌ 不采集需要登录或授权的资源
- ❌ 不使用代理池规避封禁

配置文件里请求间隔有 **1.5 秒的硬下限**——政府网站承载能力有限。

## 三、快速开始

```bash
PY=/root/miniconda3/envs/autodl-tmp/bin/python
cd /root/autodl-tmp/energy_rag

# 1. 看配置里有哪些站点
$PY -m energy_docs sites

# 2. 冒烟测试：每站只抓 5 篇
$PY -m energy_docs crawl --limit 5

# 3. 正式采集（可随时 Ctrl-C，重跑续传）
$PY -m energy_docs crawl

# 4. 导出语料
$PY -m energy_docs export --out corpus/ --single all.txt --min-chars 300
```

依赖只有 `requests` / `beautifulsoup4` / `lxml` / `tqdm`，环境里都有。

## 四、加一个新站点

**通常只需要往 `config.toml` 加几行，不用写代码。**

```toml
[[sites]]
name = "江苏省能源局"
base = "http://nyj.jiangsu.gov.cn"
entry = "/col/col12345/index.html"
link_pattern = '/art/\d{4}/\d{1,2}/\d{1,2}/art_\d+_\d+\.html'
category = "省级能源局"
```

不确定 `link_pattern` 怎么写时，用 `probe` 命令看该页所有链接的实际形态：

```bash
$PY -m energy_docs probe "http://nyj.jiangsu.gov.cn/col/col12345/index.html"
```

它会按路径形态聚类，直接告诉你内容页长什么样、该写什么正则。

## 五、已知限制

### 1. 翻页受限（最重要）

**多数政府站的列表分页拿不到。** 实测：

- 大汉版通的 `dataproxy.jsp` 接口对非浏览器请求一律返回空白（需要会话校验），
  带 Referer、X-Requested-With、POST 都试过，无效；
- `index_2.html`、`?pageNum=2`、`?page=2` 等常规分页参数返回的是**同一批内容**
  （已实测比对，首条完全相同）。

所以**默认每个栏目只能采到首屏的 15~45 条**。这是当前最大的产出瓶颈。

如果某个站的分页恰好能用，工具会自动识别并翻页；不能用时会优雅停止，不再浪费请求。

**绕过思路**（未实现，需要时再做）：维护每个栏目的完整 URL 清单（从站点地图、
搜索结果页、或搜索引擎索引里获取），而不是依赖站点自身的分页。

### 2. 栏目选择很重要

同一个站里，不同栏目的可爬性不同。实测山东能源局：

| 栏目 | 内容链接 |
|---|---|
| 动态要闻 | 44 条（静态） |
| 通知公告 | 45 条（CDATA 数据岛） |
| 法定主动公开内容 | 10 条 |
| 专题专栏 | 1 条 |

而且**动态要闻产出的是 600 字左右的短新闻，训练价值低**。
优先选「政策文件」「通知公告」「法定主动公开内容」这类栏目。

### 3. 少数站点是 JS 渲染的

列表数据完全靠 JS 加载、HTML 里什么都没有的站，当前架构拿不到。
需要时得单独找它的 XHR 接口。工具会在解析不到内容时明确告警，不会静默空军。

## 六、已经处理好的技术坑

这几个坑都是实测踩出来的，写在这里免得以后重复踩。

### 编码：服务端谎报 charset

`requests` 在响应头没声明 charset 时按 ISO-8859-1 解码，而 **Latin-1 对任意字节
序列都不报错**——结果是中文被静默解成乱码（`中华人民共和国` → `ä¸­åäººæ°'å...`），
**没有任何异常提示**。

修复：`decode_response` 不盲信声明，Latin-1 家族一律降到兜底位置，
按「声明的 charset（可靠时）→ UTF-8 → charset_normalizer → GB18030 → 声明的 charset」顺序试。

### 大汉 CMS 的 CDATA 数据岛

列表数据藏在 `<record><![CDATA[ <a href='...'>标题</a> ]]></record>` 里。
**CDATA 内的 `<a>` 被 BeautifulSoup 当作纯文本**，标准解析完全抓不到。
修复：把 CDATA 段单独再解析一遍。

### 标题里粘着发布信息

很多站的标题容器把「标题 + 发布时间 + 来源 + 大中小」塞在同一个元素里。
修复：在噪声标记处切断（`_TITLE_TAIL_MARKERS`）。

### 三段式标题

`<title>` 常是 `{站点名} {栏目名} {文章标题}`。剥站名可靠，剥栏目名用了保守判据——
**只有确认标题以站点名开头时**才再剥一段，避免把「关于 2026 年…」误剥。

### 拦截页与维护页

WAF 拦截页和站点维护页都可能返回 HTTP 200。这类页面必须识别并抛错，
否则会把「访问被拒绝」当成正文写进语料。

## 七、项目结构

```
energy_docs/
├── config.toml        站点清单 + 限速配置
├── cli.py             命令行（sites / probe / crawl / export / status）
├── fetcher.py         礼貌 HTTP + 拦截检测 + 编码处理
├── extract.py         正文抽取 + 链接抽取（含 CDATA）+ 分页接口识别
├── store.py           SQLite + JSONL，断点续传
├── crawl.py           采集编排
├── export.py          语料导出
├── adapters/
│   └── base.py        配置驱动的通用适配器
└── tests/             33 个离线测试 + 实测页面 fixtures
```

**适配器是配置驱动的**：不为每个站写代码，而是「一份站点清单 + 一个会自动尝试
多种分页策略和链接形态的通用适配器」。只有遇到真正不兼容的站才需要新增适配器。
